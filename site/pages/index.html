A CLI, and a server in two shapes. Pick the one that fits how you want to run it; the CLI supports both through different command groups.

test before relying on it

What actually triggers an alert?

Office and PDF documents

A supported reader must fetch the embedded URL. External-content prompts, Protected View, and reader settings can prevent automatic requests. PDF viewers such as browser viewers and macOS Preview may require clicking the visible link.

Text and credential bait

Reading a .txt file or copying a fake secret does not make a request. A person or tool must use the embedded URL or configured endpoint. ZIP extraction alone also does not trigger.

Devices, web snippets, and tags

Installers must be configured and reach the endpoint. Web snippets require execution or rendering. Scanning a QR code or tapping NFC must open the URL; merely viewing the label is not enough.

Verify your own setup: generate a sample, open or use it in the intended environment, and confirm the hit and notification. If it stays quiet, check the reader, network reachability, and delivery configuration.

Previews, security scanners, and crawlers can also fetch URLs. IP and browser details provide context, not a verified identity.

choose your shape

Two servers. One CLI.

One CLI supports both backends. Use mantis new and the management commands with full; use mantis edge commands with the Worker. Edge has no central key list or hit history.

stateless variant

Edge: the URL carries the configuration.

One Cloudflare Worker decrypts each URL and forwards the hit to its webhook. No database, dashboard, retry queue, or central key list. Your receiver must store the events you need.

No database to host. The URL contains the encrypted destination, channel, and memo.

Plan limits apply. Cloudflare's free plan currently allows 100,000 requests per day and 10 ms of CPU time per request. End-to-end latency depends on the network and receiver. Check Cloudflare Worker limits ↗

Deploy edge step by step

You'll need a Cloudflare account, the mantis CLI, Git, and the Node and pnpm versions specified by the product's Node version file (.nvmrc) and pnpm version (packageManager). Run each step separately in the same terminal.

1. Get the Worker
git clone https://github.com/privacykey/mantis.git
cd mantis
pnpm install --frozen-lockfile
cd mantis-edge
2. Sign in to Cloudflare
pnpm exec wrangler login
3. Deploy the Worker
pnpm exec wrangler deploy

Save the HTTPS Worker URL printed by this command. The Worker needs the secret from the next steps before URLs can trigger.

4. Generate one AES key
mantis edge keygen

Keep the generated value ready. Paste this same value into both secret prompts below. Do not generate a second key between them.

5. Store the Worker secret
pnpm exec wrangler secret put MANTIS_EDGE_KEY

Used only to prepare the next command in your browser.

6. Store the same key in the CLI
mantis edge set-key "$MANTIS_WORKER_URL"

Enter the Worker URL above to prepare a quoted command. Then paste the same AES key at the CLI prompt. With JavaScript off, set MANTIS_WORKER_URL to your deployed URL first.

7. Mint a URL
mantis edge mint

Choose the stored Worker and your real webhook destination in the wizard. Use the generated URL to make a test request, then verify the notification at the receiver.

Optional destination allowlist
pnpm exec wrangler secret put MANTIS_EDGE_WEBHOOK_ALLOWLIST

At the prompt, enter allowed webhook hosts, such as hooks.slack.com. Anyone with the AES key can mint URLs; rotating that key invalidates all existing URLs.
