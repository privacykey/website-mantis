architecture

Three pieces.

A CLI, and a server in two shapes. Pick the one that fits how you want to run it; the CLI supports both through different command groups.

// controller

mantis CLI

Terminal client. Mints keys, tails hits, generates baited files and host-event snippets.

  • mantis new · list · hits · watch · install
  • Credentials in your OS keychain
brew install privacykey/tap/mantis
// self-hosted server

mantis full

Stateful. Next.js + Postgres, web dashboard, REST API, retry queue.

  • Dashboard · timeline · multi-destination · revocation
  • Docker · Railway · Fly · Render · any VM
Deploy the full server →
// stateless worker

mantis edge

Stateless. One Cloudflare Worker, no database. The URL itself is the state.

  • Cloudflare network · no database to host
  • Anyone with the AES key can mint

capabilities

One URL, many placements.

Choose a format or installer that fits the place you want to monitor. Each requires a request to reach your deployed endpoint.

Documents · full server

Baited documents

Generate Office, PDF, RTF, HTML, and other document formats with an embedded tripwire URL. A hit requires the reader to fetch it; external-content settings and reader support matter.

Check how each file triggers →
Files · full server

A honey directory

A ZIP of documents, text files, and shortcuts tied to one key. Plain-text bait only triggers when its URL is followed. Opening the ZIP or reading passwords.txt alone does not send an alert.

Explore the bundle →
Devices · full and edge

Host-event installers

Create alarms for supported login, sudo, boot, wake, and network events on macOS, Linux, and Windows. Device bundles group relevant installers; SSH snippets can include the remote client's IP.

Choose host events →
Artifacts · full server

Credential and config bait

Generate .env files, AWS credential profiles, cookie jars, bookmarks, and connection profiles. Detection depends on using the embedded endpoint or link, not simply reading a fake secret.

See formats and mechanisms →
Provisioning · full server

Bulk creation and fleet enrollment

Create many keys together, use device bundles, and provision keys with stable external IDs. Create-only enrollment credentials support managed-device rollout without handing out an admin key.

Read the fleet guide →
Web · full and edge

Copied websites and stylesheets

Embed a CSS canary or a JavaScript clone detector. A copied page can fetch the URL when it renders. Configure the expected hostname for the JS detector; referrer information may be missing.

Explore web snippets →
Automation · full server

Smart-home triggers and actions

Home Assistant and Scrypted snippets turn automation events into hits. A Home Assistant destination can invoke your own automation in response; a LAN helper covers supported local device events.

Read the integration guide →
Physical · full and edge

NFC tags, QR labels, and Wallet

Write a tripwire URL to an NFC tag or print a QR label. A scan or tap must open the URL to trigger. Either backend can supply a tag URL. Generated Apple Wallet passes require full-server signing configuration; supported install, uninstall, and fetch callbacks can record hits.

Notifications · full server

Use your existing alerting

Send to webhook, email, Slack, Discord, Teams, or Home Assistant. A per-key status URL lets Uptime Kuma poll for a hit and use its notification integrations.

Reliability · full server

Deduplication and delivery retries

Suppress repeated alerts within a configurable window. A Postgres-backed queue retries failed deliveries with backoff and records permanent failures after the attempt limit. Monitor delivery failures as well as hits.

test before relying on it

What actually triggers an alert?

Office and PDF documents

A supported reader must fetch the embedded URL. External-content prompts, Protected View, and reader settings can prevent automatic requests. PDF viewers such as browser viewers and macOS Preview may require clicking the visible link.

Text and credential bait

Reading a .txt file or copying a fake secret does not make a request. A person or tool must use the embedded URL or configured endpoint. ZIP extraction alone also does not trigger.

Devices, web snippets, and tags

Installers must be configured and reach the endpoint. Web snippets require execution or rendering. Scanning a QR code or tapping NFC must open the URL; merely viewing the label is not enough.

Verify your own setup: generate a sample, open or use it in the intended environment, and confirm the hit and notification. If it stays quiet, check the reader, network reachability, and delivery configuration.

Previews, security scanners, and crawlers can also fetch URLs. IP and browser details provide context, not a verified identity.

choose your shape

Two servers. One CLI.

One CLI supports both backends. Use mantis new and the management commands with full; use mantis edge commands with the Worker. Edge has no central key list or hit history.

stateless variant

Edge: the URL carries the configuration.

One Cloudflare Worker decrypts each URL and forwards the hit to its webhook. No database, dashboard, retry queue, or central key list. Your receiver must store the events you need.

No database to host. The URL contains the encrypted destination, channel, and memo.

Plan limits apply. Cloudflare's free plan currently allows 100,000 requests per day and 10 ms of CPU time per request. End-to-end latency depends on the network and receiver. Check current limits ↗

Deploy edge step by step

You'll need a Cloudflare account, the mantis CLI, Git, and the Node and pnpm versions specified by the product's .nvmrc and packageManager. Run each step separately in the same terminal.

1. Get the Worker
git clone https://github.com/privacykey/mantis.git
cd mantis
pnpm install --frozen-lockfile
cd mantis-edge
2. Sign in to Cloudflare
pnpm exec wrangler login
3. Deploy the Worker
pnpm exec wrangler deploy

Save the HTTPS Worker URL printed by this command. The Worker needs the secret from the next steps before URLs can trigger.

4. Generate one AES key
mantis edge keygen

Keep the generated value ready. Paste this same value into both secret prompts below. Do not generate a second key between them.

5. Store the Worker secret
pnpm exec wrangler secret put MANTIS_EDGE_KEY

Used only to prepare the next command in your browser.

6. Store the same key in the CLI
mantis edge set-key "$MANTIS_WORKER_URL"

Enter the Worker URL above to prepare a quoted command. Then paste the same AES key at the CLI prompt. With JavaScript off, set MANTIS_WORKER_URL to your deployed URL first.

7. Mint a URL
mantis edge mint

Choose the stored Worker and your real webhook destination in the wizard. Use the generated URL to make a test request, then verify the notification at the receiver.

Optional destination allowlist
pnpm exec wrangler secret put MANTIS_EDGE_WEBHOOK_ALLOWLIST

At the prompt, enter allowed webhook hosts, such as hooks.slack.com. Anyone with the AES key can mint URLs; rotating that key invalidates all existing URLs.
