privacy

What this site does with your data.

Short answer: nothing it doesn't have to. This page is the long answer — every outbound request this website makes, what data crosses the wire, and how to make it quieter if you'd rather.

No personal data collected

No cookies, no analytics, no fingerprinting, no third-party trackers. We don't run a server that records your visit.

Third parties this website talks to

Most of the site is static — HTML, CSS, a couple of small scripts, and Three.js for the 3D globe. None of that calls anywhere off our origin. There's exactly one outbound endpoint, listed below.

GitHub Actions build status

The footer shows the latest CI run for the mantis repo (passing / failing / running). To get that signal, one anonymous API call runs on page load.

GitHub — public REST API

Optional
api.github.com/repos/privacykey/mantis/actions/runs?per_page=1
When it runs
Once on first page load. Result is cached in localStorage for 5 minutes, so reloads and inter-page nav don't re-hit the API.
What we send
A standard unauthenticated GET request. Your IP, your User-Agent, and an Accept header — nothing else. No cookies, no identifiers.
What we receive
JSON describing the most recent workflow run: status, conclusion, timestamps. We use one of those fields to colour the build badge.
How to disable
Block api.github.com in your browser, or use a content blocker. The badge will hide itself when the request fails; nothing else on the page depends on it.

What we don't do

  • No cookies. The site sets none, reads none, and works fine in private-browsing mode with all storage cleared.
  • No analytics. No Google Analytics, no Plausible, no Fathom, no in-house pixel. We don't count visits.
  • No third-party fonts, scripts, or images. Everything except the GitHub API call above is served from this origin.
  • No ads. There are no advertising networks, no remarketing pixels, and no affiliate links.
  • No social embeds. Twitter / X, YouTube, etc. all load tracking content; we don't embed any of them.

localStorage — what stays in your browser

Two small keys are written to localStorage on this origin. Neither leaves your browser, and you can clear them at any time from your browser's storage settings.

  • mantis-theme — which colour theme (mono / amber / green / cyan) you picked from the dropdown, so the choice survives reloads. Default: mono.
  • mantis-build-status — the cached GitHub Actions result, with a 5-minute TTL. Lets the footer paint instantly on inter-page nav without re-hitting the API.

What mantis itself does (the software)

This site is marketing. The actual mantis software you'd install on your own infrastructure has a different threat model and a different set of outbound calls — by definition, since the whole point of mantis is to receive HTTP requests and forward notifications.

For a default install of mantis full on your own server:

  • Inbound: a unique /c/<id> URL accepts hits from anywhere on the public internet (that's the canary trigger). The server records the hit's IP, User-Agent, headers, and timestamp into your Postgres.
  • Outbound: whatever notification destinations you configure — webhook, email, Slack, Discord, Teams, Home Assistant, or Uptime Kuma. Nothing else.
  • No telemetry phones home. mantis doesn't call privacykey, doesn't report version, doesn't ping for updates.

For mantis edge on Cloudflare Workers, the same shape holds — but the data crosses Cloudflare's infrastructure, so their privacy policy applies in addition to whatever you configure on top. Cloudflare sees your visitors' traffic the same way they would for any Worker.
